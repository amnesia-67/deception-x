## Exact model identity and preprocessing differences

The current [V-JEPA2.1 wrapper](https://github.com/amnesia-67/sunhacks-2026/blob/9c11432c953dcbe653d637dcd2f2814ba7590d57/src/backbones.py#L153) is **ViT-B/16 at 384**, output width 768, consuming 32 frames. This differs from the earlier ViT-L, width 1024, 64-frame configuration; the user has now explicitly accepted ViT-B temporarily while the teammate retrains ViT-L. The architecture choice is resolved and is not an approval blocker. [MODEL_SOURCES.json](https://github.com/amnesia-67/sunhacks-2026/blob/9c11432c953dcbe653d637dcd2f2814ba7590d57/models/MODEL_SOURCES.json) names `vjepa2_1_vitb_dist_vitG_384.pt` and approximately 86.8M parameters. ViT-B LoRA tensors cannot be loaded into ViT-L by renaming or reshaping keys. Deploy and label the accepted ViT-B profile accurately; keep the planned ViT-L retraining separate and do not interchange their adapters.

The [preprocessor](https://github.com/amnesia-67/sunhacks-2026/blob/9c11432c953dcbe653d637dcd2f2814ba7590d57/scripts/preprocess_rlt.py#L60) samples 128 timestamps uniformly across an entire variable-duration clip. It selects a largest/confident BlazeFace face, interpolates and median-smooths face boxes, expands a square crop by 1.6, and resizes it to 384. [The view code](https://github.com/amnesia-67/sunhacks-2026/blob/9c11432c953dcbe653d637dcd2f2814ba7590d57/src/clip_store.py#L54) chooses a 64-cached-frame half-clip, with ViT-B taking 32 frames at stride 2 and evaluation averaging both half-clip views. This is variable effective FPS and clip-wide context, not the Mac's fixed 24 fps, 64-frame, 2.625-second full-scene recipe. A live adaptation needs an explicit versioned contract and quality caveat, not a claim of exact training equivalence.

Other important current contracts in [backbones.py](https://github.com/amnesia-67/sunhacks-2026/blob/9c11432c953dcbe653d637dcd2f2814ba7590d57/src/backbones.py):

- Audio is 16 kHz mono. Training selects up to 16 seconds with gain augmentation; evaluation uses a centered window up to 60 seconds. Temporal reduction uses adaptive average pooling when there are more than 32 frames, and linear interpolation only when upsampling. This differs from the old adapter's linear resize for every length.
- Qwen now uses a fixed testimony-analysis instruction prefix, a 512-token cap, last-position pooling with left padding, first 128 dimensions and L2 normalization. Raw unprefixed Mac transcripts are a different feature contract.
- Emotion2vec contributes 1024-dimensional temporal features; Dasheng contributes 768. The new fusion uses both.

The new [fusion](https://github.com/amnesia-67/sunhacks-2026/blob/9c11432c953dcbe653d637dcd2f2814ba7590d57/scripts/train_stage2.py#L152) is also different from the old three-projector export: it concatenates frozen V-JEPA2 ViT-L1024 and V-JEPA2.1 ViT-B768 tokens into 1792 visual channels, and frozen Dasheng 768 plus emotion2vec 1024 into 1792 audio channels, with 128 text channels. It standardizes features using inner-training means/stds and averages five seed models. It does not feed tuned-backbone features into that fusion. The reviewed function saves predictions and reports but does not persist the fusion model states or those normalizer statistics. The old `branch1_fusion.pt` was deleted. Reusing the old synthetic head would therefore silently restore the wrong model.

[The export script](https://github.com/amnesia-67/sunhacks-2026/blob/9c11432c953dcbe653d637dcd2f2814ba7590d57/scripts/export_deploy.py) currently exports **only** the real-data XGBoost booster and its 89-feature schema. Random-placeholder defaults have been correctly removed, but a `jepa_loaded` boolean would still identify only that optional head, not the tuned video backbone.
