# Hackathon showcase

The default localhost page and `/showcase` serve `sunhacks/static/showcase.html`; `/dashboard` and `/index.html` retain the technical dashboard. Use the existing `./scripts/run.sh` launcher and the verified split profile. Model preparation begins without sensors.

The showcase owns one session at a time. Practice is optional and does not supply a personal calibration profile. The main action starts the seven-second test directly. Optional Practice first begins camera and Blue Snowball capture. Its15second warmup clock starts after camera/audio are running and a real frame has actual audio coverage. Three 5 second prompts ask for two truths (name/nickname, school/role) and a harmless lie. These labels are participant instructions and are not verified. The warmup checks recording continuity and nonzero microphone signal, without transcription, model inference, personal calibration, training, saving raw media or sending media elsewhere. Frames are discarded on drain; the PCM buffer retains at most two seconds.

After optional practice devices stop, Ready offers the same seven-second test. The participant privately chooses truth or lie. `Pipeline.start(..., auto_stop_seconds=7.0)` starts its timer from the first usable synchronized source frame, rather than the browser request. A server monotonic deadline trims any late frames at the cutoff and stops sensors even when browser polling pauses. Actual first-to-last frame span can be slightly below 7 seconds because capture is discrete. The unchanged real split runtime processes the answer; its audio/text/ensemble stay on the Mac, and video alone goes to the verified GPU.

A result needs matching session/window IDs, a nonmock answer, available video, tuned Dasheng, frozen Qwen/emotion, the trained digest/stack, complete audio coverage and a nonempty same-answer local transcript. The old unavailable ReDA head is intentionally excluded. The display follows the pinned teammate serving rule: class-1 score ≥ 0.5 is labeled 'model leans toward a lie'; otherwise 'model leans toward truth'. Missing or invalid inputs yield Inconclusive. Video is checked separately and is not added to the learned local stack. Raw scores are not displayed as confidence percentages. The threshold and predictions are not personally calibrated and do not establish deception.

Cancel is independent of ordinary UI requests and remains visible while scrolling, including the Ready stage. Escape cancels too. The server serializes all POST actions and blocks dashboard capture/preparation mutations while showcase ownership is active. Generation and session checks prevent old timers/results from affecting a newer participant. Reset cancels and clears prior in-memory answer/transcript/diagnostics while retaining prepared weights. Application shutdown closes the showcase before releasing the pipeline.

An explicit Check model connection action is available after cancellation when the GPU connection needs re-verification. Preparation opens no sensors.

The [calibration research decision](CALIBRATION_DECISION.md) documents why three practice examples do not alter the existing model rule or exported Platt scaling.

Tests use fake sensors/clocks/models to cover 15 second prompts, device startup delay, 7 second cutoff/overrun, cancellation, stale generations, missing branches, result provenance, shared dashboard ownership, new-participant clearing and UI failures. Existing actual model live timing measurements remain separate; the complete new guided flow needs a participant practice run to measure its native capture and total timing.
