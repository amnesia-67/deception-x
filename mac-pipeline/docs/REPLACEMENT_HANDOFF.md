# Replacement model handoff

**Current state:** earlier teammate artifacts are quarantined. Training and dataset acquisition happen on the teammate's machine. This Mac build does neither. The intended datasets are those in [the user's shared plan](https://share.gemini.google/J6DolcFfkQKZ); do not infer that the earlier synthetic generator implemented them.

Send these items together with replacement weights, rather than sending a checkpoint alone:

1. Exact source commit and model class/forward implementation; artifact architecture/version, strict state-key schema, file SHA256, license, explicit output/class ordering and score semantics.
2. Each backbone's exact model ID, base revision and checkpoint hash. Preserve the distinction between V-JEPA2 and V-JEPA2.1. User preference remains V-JEPA2.1 ViT-L; a different backbone/preprocessing must be explicitly reviewed, not relabelled because both emit 1,024 features.
3. The actual training extraction recipe: camera/window sampling, clip timestamps, RGB resize/crop/normalization, audio sample rate/normalization, sequence pooling/resizing and any audio adapter order. State whether sequences or pooled vectors feed the new head. Do not inherit first128 Qwen slicing or 32-step audio resizing merely because the withdrawn synthetic head used them.
4. Text source, token limit, pooling/normalization and timing scope (same-window ASR versus session context). List the role of emotion2vec explicitly. LoRA exports require exact base/targets/rank/alpha and safetensors/config hashes; a dense audio adapter is not a backbone LoRA export.
5. For a behavioral model, the complete **ordered** field schema with extraction implementation, units, expected ranges, normalization/baseline parameters, timing and missingness policy. An unnamed 250-wide array is insufficient. This Mac currently implements only seven quality diagnostics and will not fill the other fields with invented values.
6. Dataset versions and genuine subject/speaker-disjoint split identifiers, preprocessing exclusions and held-out metrics. Keep calibration fitting separate from reported evaluation. Supply calibration/stacking inputs and sign conventions; never simulate a cloud score from ground-truth labels.
7. A small deterministic **non-person technical inference fixture** and expected outputs from the training machine, plus tolerances, to verify loading and cross-device numeric parity. No dataset transfer is required for this plumbing check.
8. For remote video, provide the actual server source and a health schema distinguishing encoder loaded from fusion head loaded. It must accept timestamped video frames and run the real checkpoint. [GPU_ENCODER_PROTOCOL.md](GPU_ENCODER_PROTOCOL.md) is a prepared new contract, not proof that the stopped server already implements it.

The proposed fast capture profile is 30 fps requested camera capture, 64 distinct frames selected at 16 fps (3.9375-second first-to-last span), 4-second hop, aligned 16 kHz mono audio. This is a proposal to confirm against training, not an already validated quality recipe. Native V-JEPA2.1 ViT-L/384 input remains `[1,3,64,384,384]`; native token output is `[1,18432,1024]`. Spatial means per temporal tubelet would give `[32,1024]` if that is the actual new head contract. Native Dasheng hidden sequences are variable-time ×768; Qwen's configured pooled embedding is1024; emotion2vec utterance output is1024. The final head's field sizes and transforms must match **actual training**, not guesses from vector width.

New artifacts get a separate versioned directory/profile. Inspect source before import, verify hashes and strict keys, compare the technical fixture, then measure the full path before activating a live demo. Do not overwrite the old file beneath its hardcoded audited hash or bypass quarantine. Actual recorded-data validation remains distinct from compatibility and latency tests; none of these checks establishes reliable deception detection.
